# Tokyo Bus Mate

日本語が苦手な訪日外国人観光客が、路線バスに乗るときの不安を減らすためのWebサービスです。
バスの系統番号・行き先表示と、降車停留所の日本語名・ローマ字表記を確認できます。

現在のプロトタイプは、都営バス上23系統を利用する次の案内に対応しています。

- 目的地：上野動物園
- 目的地：上野公園
- 目的地：上野駅
- 目的地：上野松坂屋
- 乗車停留所：浅草雷門、浅草一丁目、浅草寿町
- 降車停留所：上野公園山下、上野駅前、上野松坂屋前
- バスの行き先表示：上野松坂屋前

上記の乗降順と同じ便で移動できることは、同梱GTFSデータを使って確認しています。
画面右上のボタンで日本語・英語を切り替えられます。実際の車両表示と照らし合わせるため、
系統番号やバスの行き先表示は日本語のままです。

## 主な機能

- 登録済みの観光地から目的地を選択
- 選択した目的地に対応する乗車停留所を選択
- 系統番号、行き先表示、乗車停留所を確認
- 乗車停留所から降車停留所までの停車順を確認
- 降車停留所の日本語名とローマ字を確認
- GTFSに記載された運賃を表示
- 日本語・英語の画面表示を切り替え

車両写真は、掲載許可を得た画像を用意するまで仮表示です。
リアルタイムの運行情報、現在地、降車カウントダウンには対応していません。

## 開発者向けルール

### ブランチ運用

- 通常の開発は `dev` ブランチで行います。
- 変更の規模に応じてテストを実行し、動作に問題がないことを確認してから `main` に反映します。
- `main` はGitHub Pagesで公開する安定版として扱い、直接の作業ブランチにはしません。
- 将来の機能をまとめて管理する必要が出た場合は、`future` ブランチを作る案があります。作成するかどうかは、開発体制や機能の範囲に応じて決めます。現時点で作成済みのブランチとしては扱いません。

### コミットメッセージ

コミットメッセージは、次の形式で記述します。

```text
英語の動詞: 変更内容
```

例：

```text
Add: destination selector
Fix: stop order validation
Update: Japanese README
```

英語の動詞は変更の内容に合わせて選び、コロンの後には変更内容を簡潔に書きます。

### テストと公開

- JavaScriptの変更後は、少なくとも `npm test` を実行します。
- GTFSの元データや目的地との対応を変更した場合は、`npm run process:gtfs` で加工データを再生成し、テストを実行します。
- 画面に関わる変更では、目的地選択からバス案内までを確認します。特にモバイル相当の画面幅でも表示が崩れないことを確認します。
- `dev` で変更と必要なテストを確認し、問題がなければ `main` に反映します。
- `main` に反映した内容をGitHub Pagesで公開します。公開後は実際のページで、JSONの読み込みと主要画面の動作を確認します。

このプロジェクトはHTML・CSS・JavaScript・JSONで動作する静的サイトです。
GitHub Pagesで公開できる構成を維持し、相対パスを使ってプロジェクト用URL配下でも動作するようにします。
秘密情報や公開許可のない写真・データを公開対象へ含めないでください。

## データの更新と確認

`ToeiBus-GTFS/` 内の元データは加工スクリプトから読み取るだけで、変更しません。
GTFSデータを更新した場合は、次のコマンドでブラウザー用のデータを作り直します。

```text
npm run process:gtfs
```

加工スクリプトは、設定された乗車停留所と降車停留所が同じ便に含まれ、
乗車後に降車できる順序になっているかを確認します。
運行カレンダーと特定日の例外も、フィード開始日について確認します。
ブラウザーが使うのは `data/destinations.json` と
生成された `data/bus-routes.json` で、GTFS一式をそのままダウンロードしません。

新しい目的地を追加するときは、観光地と停留所の対応を
`data/destinations.json` に登録します。路線、行き先表示、停留所順序、運行日を
GTFSで確認してから追加し、加工とテストを行ってください。
停留所名が似ていることだけを根拠に、対応関係を決めないでください。

## テスト

```text
npm test
```

このテストでは、停留所順序、案内データの組み立て、日本語・英語の翻訳文、
HTMLで使う翻訳キー、GTFSから生成された乗車停留所データを確認します。
各目的地の案内に、乗車停留所から降車停留所まで順序どおりの経路が含まれることも確認します。

## ファイル構成

- `index.html`：画面の構造と表示文言のキー
- `css/style.css`：画面の見た目
- `js/main.js`：初期化、選択操作、案内表示、言語切り替え
- `js/busService.js`：JSON読み込みとバス案内データの組み立て
- `js/routeUtils.js`：乗車・降車停留所の順序判定
- `js/translations.js`：日本語・英語の画面文言
- `data/destinations.json`：観光地と路線・停留所の対応表
- `data/bus-routes.json`：GTFSから生成した路線、停留所、運賃、検証情報
- `scripts/process-gtfs.js`：GTFSからブラウザー用JSONを生成するスクリプト
- `tests/routeUtils.test.js`：経路判定と生成データのテスト
- `ToeiBus-GTFS/`：加工前の都営バスGTFSデータ

## データ出典と公開時の注意

- GTFSの `attributions.txt` には、東京都交通局と公共交通オープンデータ協議会が記載されています。
- 公開前にデータの最新のライセンスとクレジット要件を確認し、必要な表記を公開ページに含めます。
- 運賃210円はGTFS記載値です。この路線のIC運賃はGTFSに記載されていません。一般公開前に運行事業者へ運賃ルールを確認してください。
- 車両写真を掲載する場合は、チームで撮影・保有するなど、Web公開の許可を得た画像を使用します。
- 東京スカイツリー最寄りの停留所は、同梱GTFSでは浅草雷門・浅草一丁目・浅草寿町から乗車後に到達する同一便が確認できませんでした。そのため、現時点では目的地に追加していません。別路線や乗り換えを含めて案内する場合は、対象範囲と経路の検証を改めて行います。
